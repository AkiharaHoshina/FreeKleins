# 01 · 客户端画像与二进制补丁

## 技术栈

| 项 | 值 |
|---|---|
| 引擎 | Unity **2020.3.47f1** |
| 脚本后端 | **IL2CPP**（Metadata v27 / IL2CPP 27.1），x86-64 |
| Lua 层 | **tolua** + **LuaJIT 2.1.0-beta3**（`Plugins\x86_64\tolua.dll`） |
| Lua 形态 | **已剥离调试信息的 LuaJIT 字节码**（`string.dump(f, true)`，flags `0x0A` = `STRIP|FR2`），**未加密** |
| 资源 | 21073 个 AssetBundle（约 7.8 GB），**明文 UnityFS**；文件头有 8 字节 `0x20` 前缀，真实头在偏移 **+8** |
| HTTP 客户端 | **BestHTTP/2 v2.5.3** |
| 业务协议 | 裸 TCP + protobuf + XXTEA（见 [03](03_业务层_10301_CSPKG.md)） |

## 唯一必要的一处二进制补丁

整个客户端只改了 **一个字符串**，用于把服务器地址从官方域名指向本机。

- **文件**：`环行旅舍_Data\resources.assets`
- **偏移**：`0xFE948`
- **对象**：`game_conf`（`GameConfig` ScriptableObject）的 `PlatfromUrl` 字段
  （注意字段名就是拼错的 `PlatfromUrl`，不是 `PlatformUrl`）

| | 值 | 长度 |
|---|---|---|
| 原始 | `https://base-product.bingkolo.com:10300/` | 40 字符 |
| 改后 | `http://127.0.0.1:10300/kleins/origin/v1/` | 40 字符 |

### 为什么必须等长

Unity 序列化的 string 是 `int32 长度 + 内容 + 4 字节对齐填充`。
新旧内容都是 40 字节 → 字段总长 4+40 = **44 字节**（正好 4 对齐，无填充）→
**文件体积不变、其后所有偏移不变**，所以不需要重排任何资源表。

### 这样改的好处

- 不动 `GameAssembly.dll`，不动 IL2CPP 元数据
- **不需要改 hosts**、**不需要管理员权限**、**不需要自签证书**
  （用户明确要求"不提权"）
- 端口仍是 10300，所以 `routes.json` 里所有 URL 都按 10300 写

### 工具与备份

- 改文件：`python D:\KleinsPatch\_re\gameconf.py`
- 原始备份：`D:\KleinsPatch\_re\resources.assets.orig`

> 路径里带 `/kleins/origin/v1/` 是刻意加的：客户端会把 `baseapi/v1/...` 等相对路径拼在后面，
> 加一层前缀后，假服务端就能用"路径后缀匹配"来路由（见 [02](02_HTTP层_10300.md)），
> 不必知道前缀是什么。

## Lua 资源树的加载路径

`LuaResLoader` 是从**资源树** `Win\lua\...` 里读 Lua 的，**不是**从工作目录。
所以任何 Lua 覆盖都必须写进 `D:\KleinsPatch\Win\lua\` 下对应的相对路径，
`require("logic/xxx/yyy")` 才能命中。参见 [05](05_客户端Lua覆盖清单.md)。
