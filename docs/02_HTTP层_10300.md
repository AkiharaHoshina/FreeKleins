# 02 · HTTP 层（`fakeserver.py` / `fakeserver.exe`，端口 10300）

客户端在登录前那一大段（检查更新、拉配置、拉公告、账号、实名）全部走 HTTP。
这一层由 `fakeserver.py` 顶替，源码只有一百多行，**路由表外置**。

## 响应信封（硬性要求）

所有 HTTP 响应都必须是这个 JSON 形状，**三个键都要在**：

```json
{ "code": 0, "msg": "ok", "data": { ... } }
```

`code != 0` 客户端会走错误分支；`data` 缺键会拿不到后续地址。

## 路由表：`routes.json`

**每次请求都重新读盘**，所以改完 `routes.json` **立即生效，不用重启服务端**。

匹配规则（见 `resolve()`）：

1. 先精确匹配 `"方法 路径"`（如 `"POST /a/b"`）；
2. 再按**路径后缀**匹配（键里不含空格，`path.endswith(key)` 或 `key in path`）；
3. 都不中 → `__default__`（`{"code":0,"msg":"ok","data":{}}`）。

第 2 条就是前面加 `/kleins/origin/v1/` 前缀的原因：客户端真实请求
`POST /kleins/origin/v1/baseapi/v1/update`，而路由表里只写 `baseapi/v1/update` 就能命中。

## 已配置的路由

| 键（后缀） | 谁在调 | 关键字段 |
|---|---|---|
| `baseapi/v1/config` | 启动时拉全局配置 | `data.env`(int)、`envName`、`accUri`、`idcardUri`、`noticeUri`、`noticeWebUri`、`serviceUri`、`exchangeUri`、`logUri`、`orderUri`、`partUri`、`gameServerUri` |
| `baseapi/v1/update` | 检查更新 | `data.updateType`(string)、`updateList`(**空数组即跳过更新**)、`resUrl`、`bin` |
| `baseapi/v1/getResVer` | 同上（备用入口） | 同 `update` |
| `notice/api/notice/v1/getMaintainNotice` | 维护公告 | `data.id = 0` |
| `notice/api/notice/v1/getGeneralNotice` | 通用公告 | `data.id = 0` |
| `acc/api/acc/v1/login` | 账号登录 | `data.userId`、`token`、`logOffTime`、`isVirtual` |
| `idcard/api/idcard/v1/query` | 实名认证 | `data.status=0`、`age`、`birthDay`、`pi`、`idNum` |
| `__default__` | 兜底（含 `log/api/clientlogsvr/v1/reportError`） | `{"code":0,"msg":"ok","data":{}}` |

### `gameServerUri` 是关键

它是一条**被序列化成字符串的 JSON 数组**，客户端解析出业务服地址：

```json
"[{\"serverId\": 1, \"serverName\": \"LocalServer\", \"ip\": \"127.0.0.1\", \"port\": 10301}]"
```

`port: 10301` 就是 `bizserver` 的端口。业务服不是 HTTP，是裸 TCP，见 [03](03_业务层_10301_CSPKG.md)。

### `updateType` 的判定

客户端对 `updateType` 做 `Contains("bin")` / `Contains("res")` 判断走哪条更新分支。
这里给 `"res"`，同时 `updateList` 给**空数组** → 客户端认为"无更新"，直接放行。
