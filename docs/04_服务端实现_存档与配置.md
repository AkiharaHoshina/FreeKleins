## 4.2 存档 `player.json`

```jsonc
{
  "actor": { "accId": 10000001, "name": "Kleins", "level": 10, "exp": 0,
             "intellect": 120, "diamond": 99999, "gold": 99999999, "copper": 99999999 },

  "roles": { "1001": { "level": 1, "exp": 0, "strength": 0, "potential": 0,
                       "ability": 1, "skin": 0 }, ... },

  "items": { "1": 50000000, "3": 50000000, "5": 50000000, "75": 50000000 },

  "stages":   { "<type>:<chapter>:<main>:<minor>": score },   // 通关记录
  "chapters": { "<type>:<chapter>": 1 },                      // 章节开放
  "cockpit":  { "<position>": roleId },                       // 驾驶舱摆放

  "groups": {                                                  // 编队
    "1": { "name": "编队一", "members": [[1001, 0], [1003, 1], ...] },
    ... 到 "6"
  },

  "recruit": { "up_pity": 0, "normal_pity": 0 }                // 保底计数
}
```

### 编队：为什么是稠密列表

原版编队就是**稠密**的：10 个位置，撤掉第 4 个，第 5..10 个会上前补位。
`playerdata.load()` 每次读档都会**去掉 `roleId == 0` 的空洞**：

```python
gg["members"] = [m for m in mem if int(m[0]) != 0]
```

> 曾经做过"槽位制（允许空洞）"的实验（`inject_queue_slot.py`），
> 会导致多选崩、界面不刷新，**已整体回退**。回退脚本已验证与原始备份**逐字节相同**。

`GROUP_NAMES` / `GROUP_COUNT` / `MAX_MEMBER`：

```python
GROUP_NAMES = {"1":"编队一", "2":"编队二", "3":"编队三", "4":"编队四", "5":"", "6":""}
GROUP_COUNT = 6      # 客户端 QueueIndex 枚举: 1..4 编队, 5=无尽, 6=锁定队
MAX_MEMBER  = 10
```

### 默认角色 1001..1005

初始存档给 5 个角色、满资源、第一编队预置这 5 个，**打开就能直接开战**。
抽卡抽到新角色会自动入库。`reset_roles()`（由 `1127` 触发）会把角色表重置回这 5 个。

## 4.3 人物数据构造中的坑

### `TalentList` 的 `Step` 不能是 0

`build_role()` 会输出天赋列表：

```python
for rank, _mx in cfgdata.role_ranks(role_id):
    r += bs(6, uv(1, rank) + uv(2, int(steps.get(str(rank), 1))))   # Step 默认 1
```

客户端 `logic_role_data.UpdateRoleData` 会把 `Rank/Step` 抄进角色数据，
`Step` 会被拿去查 `dataconfig_talent_cfg(id, level=Step)`——**这张表的 `level` 从 1 开始**。

给 0 会查空 → 编队界面 `UpdateRoleItem` 崩在 `TGETS 'skill_type'` 上。
表现：**图标已经画完了，但名称/品质/等级/命之座全是占位符**。默认 `Step = 1` 即可。

### `CSLoginRes` 的 body 不能为空

客户端把**空的响应 body** 当成 `ENM_STATUS_CLIENT_TIMEOUT`，提示"网络异常"。
所以关键回包（至少登录）必须有内容：

```python
body = pb_v(2, now) + pb_v(3, 1) + pb_v(8, now) + pb_v(10, 0)
```

## 4.4 角色升级的计算链

`playerdata.apply_level_up(pd, role_id, use_list)`：

```
每级所需经验 = dataconfig_star_levelup[star, level].exp
材料经验     = dataconfig_itembase[itemId].args[1] * count
等级上限     = dataconfig_star_strengthen[star, strengthStep].max_level
金币消耗     = Σ(每级消耗经验) * money_count / 100
```

`UseList` 是**客户端**告诉服务端"本次要吃哪些材料"；升几级由服务端算，一直升到材料不够为止。
材料从 `items` 里扣，金币从 `actor.gold` 里扣。

## 4.5 配置表 `cfg\`（58 张）

这些是**从运行时 dump 出来的真实 Lua 表文本**（用 `inject_cfgdump.py` 挂进游戏导出的），
不是从 AssetBundle 里猜的。文本形如：

```
1 =>
{
    weight = 50,
    id = 1,
    up_role = { [1] = 1046, },
    pool_name = "18045",
}
```

`cfgdata.load(name)` 把它解析成 `{行主键: {字段: 值}}`（带缓存）。

### `cfgdata.py` 提供的查询

| 函数 | 用途 |
|---|---|
| `load(name)` | 读整张表 |
| `recruit_pools()` | `[(pool_id, pool_type, pool_name, up_roles, one_cost, ten_cost), ...]` |
| `pool_roles(pool_id)` | 某池的角色 `[(role_id, weight), ...]` |
| `all_role_ids()` | 全部角色 id |
| `role_star(role_id)` | 稀有度（`dataconfig_role_config.star`，4 = SSR） |
| `max_role_level(star, step)` | 等级上限 |
| `level_cost(star, lvl)` | `(所需经验, 每100经验的金币)` |
| `item_exp(item_id)` | 经验道具的经验值（`itembase[id].args[1]`） |
| `role_ranks(role_id)` | 天赋阶位 `[(rank, max_step), ...]` |
| `role_skin_ids(role_id)` / `all_skin_ids()` | 皮肤 id |

### 关键表一览

`dataconfig_recruit_pools`（卡池）、`dataconfig_recruit_pool_role`（池内角色权重）、
`dataconfig_role_config`（角色主表）、`dataconfig_role_talen_rank`（天赋阶位）、
`dataconfig_star_levelup` / `dataconfig_star_strengthen`（升级曲线与上限）、
`dataconfig_itembase`（道具）、`dataconfig_stage_minor` / `dataconfig_stage_chapter`（关卡与章节）、
`dataconfig_activity_time`（活动时间窗）、`dataconfig_skin_config`（皮肤）、
`dataconfig_shop_*`（商店，6 张）、`dataconfig_system_mail`（邮件）、`dataconfig_task_base`（任务）…

## 4.6 打包成 exe 时的路径处理

PyInstaller `--onefile` 运行时，`__file__` 指向临时解包目录，不是 exe 所在目录。
所以两个服务端都加了这段（否则读不到 `cfg\` / `routes.json`）：

```python
def _base_dir():
    if getattr(sys, "frozen", False):
        return os.path.dirname(os.path.abspath(sys.executable))
    return os.path.dirname(os.path.abspath(__file__))
```

`player.json` / `settings.json` / `bizdata.json` / 各日志用的是**绝对路径**
（写死 `D:\KleinsPatch\_re\...`），所以 exe 从哪启动都行；
但 exe 自身必须待在 `_re\` 里，跟 `cfg\`、`routes.json` 放一起。
